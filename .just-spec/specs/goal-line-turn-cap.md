# Goal

`/just-spec:spec` が spec 確定時に提示する `/goal` 実行行に、10ターンの上限節と、上限到達時の報告要求を追加する。spec に欠陥があって収束しない無人実行が、無限ループとトークン消費の爆発に至るのを防ぐ。README（英日）の提示行サンプル・同席依頼文・上限の位置づけの説明を同期する。

## Context

`/goal` の公式ドキュメントは、長いターンにわたって成立する条件の要素として「測定可能な1つの終了状態 / 証明方法の明示 / 守るべき制約」を挙げており、現行の提示行はこの3要素を満たしている（全 AC PASS ＝ 終了状態、Evidence 表 ＝ 証明方法、Constraints 非違反 ＝ 制約）。公式はこれに加えて、実行時間を制限するために `or stop after 20 turns` のようなターンまたは時間の節を条件に含めることを推奨している。現行の提示行にはこの節がなく、これが唯一の欠落である。

上限は目標値ではなく破滅の防止線である。spec が完結していれば実行は少ないターンで終わることが期待され（実績: AC 20個の予約機能が1ターンで完走）、上限が発動する状況とは spec または環境に構造的な問題がある状況である。上限値 10 はこの前提で「異常時にいくらまで払うか」として人間が決めた値であり、正常な作業分割・環境要因・エスカレーション報告の組み立てを見込んでも届かない水準である。

提示行の現存箇所は3つ: `plugins/just-spec/skills/spec/SKILL.md` のひな形、`README.md` と `README.ja.md` のサンプル。同席依頼文（`/goal` 非対応環境向け）は README 英日に1つずつある。`scripts/validate.mjs` が SKILL.md の必須不変フレーズと語数予算（1250語。現在ちょうど 1250/1250 で余裕ゼロ）を CI で検査している。

## Requirements

- **R1:** SKILL.md の `/goal` 提示行ひな形の条件に、公式の書式に沿った10ターンの上限節を追加する。趣旨の参考: `..., or stop after 10 turns even if not done.`（文言は既存の提示行の文体に合わせて調整してよい）。
- **R2:** 上限到達で停止する場合の報告要求を提示行の条件に含める: 完了を宣言せず、その時点の状態（PASS 済みの AC / 未達の AC とその理由 / 実行した内容の要約）を報告して止まること。既存の「充足不能・連続失敗時は経緯と質問を報告して停止」の要求と一貫した文体にする。
- **R3:** 上限値 10 は SKILL.md のひな形に定数として直書きする。設定可能にしない（変更したい場合はスキルを編集する）。
- **R4:** 追加後も提示行は定型であり、差し込む可変部分は spec のパスのみとする。spec の規模によらず長さは一定で、パスを埋めた実体が 1,000 文字以内（`/goal` の 4,000 文字上限に対して十分な余裕）を保つ。
- **R5:** `README.md` と `README.ja.md` の提示行サンプルを、更新後のひな形にプレースホルダパスを埋めたものと一致させる。
- **R6:** README 英日の同席依頼文に同じ上限の趣旨を反映する: 10ターンで全 AC に至らない場合は完了とせず、状態を報告して停止すること。
- **R7:** README 英日に上限の位置づけを1〜2文で記載する: 上限は期待値ではなく暴走防止であり、spec が完結していれば通常は少ないターンで完了する。上限に達した場合は spec の欠陥を疑い、報告された未達 AC から原因を確認する。
- **R8:** 🤖 `scripts/validate.mjs` の SKILL.md 必須フレーズ検査に、上限節の存在を検出するフレーズを追加する。既存フレーズ `/goal Implement the spec at <spec-path>` の検査は維持する。
- **R9:** 🤖 バージョンを 0.7.2 に上げ、`package.json` / `.claude-plugin/marketplace.json` / `plugins/just-spec/.claude-plugin/plugin.json` を揃えて `CHANGELOG.md` に追記する。

## Acceptance Criteria

すべての AC は、対象ファイルの該当箇所の引用またはコマンドの実行結果で確認できる。引用と実行結果を報告に出力することが、そのまま Evidence となる。

- **AC1:** `plugins/just-spec/skills/spec/SKILL.md` の提示行ひな形に、10ターンで停止する上限節と、上限到達時に完了を宣言せずその時点の状態（PASS 済みの AC / 未達の AC とその理由 / 実行した内容の要約）を報告して停止する要求が含まれている。数値 10 がひな形に直書きされ、上限を設定・変更する機構への言及がない。
- **AC2:** ひな形の可変部分が spec パスのプレースホルダのみであり、代表的なパス（例: `.just-spec/specs/goal-line-turn-cap.md`）を埋めた実体の文字数が 1,000 文字以内である（パスを埋めて文字数を数えたコマンド出力で確認できる）。AC の数や spec 固有の内容を含まない。
- **AC3:** `README.md` と `README.ja.md` の提示行サンプルが、更新後のひな形にプレースホルダパス（`.just-spec/specs/<slug>.md`）を埋めたものと文字単位で一致する（比較コマンドの出力で示せる）。
- **AC4:** `README.md` と `README.ja.md` の同席依頼文に、10ターンで全 AC に至らない場合は完了とせず状態を報告して停止する趣旨が含まれており、英日で同等の内容である。
- **AC5:** `README.md` と `README.ja.md` に、上限が期待値ではなく暴走防止であること、spec が完結していれば通常は少ないターンで完了すること、上限に達した場合は spec の欠陥を疑い報告された未達 AC から原因を確認することが、1〜2文で記載されている。
- **AC6:** `node scripts/validate.mjs` が終了コード 0 で成功する。
- **AC7:** `scripts/validate.mjs` の必須フレーズ検査に上限節を表すフレーズが含まれ、SKILL.md から上限節を意図的に取り除いた状態で実行すると失敗する（壊した状態の実行出力と、復元後の成功出力で示せる）。
- **AC8:** `package.json` / `.claude-plugin/marketplace.json` / `plugins/just-spec/.claude-plugin/plugin.json` のバージョンが 0.7.2 で一致し、`CHANGELOG.md` に 0.7.2 のエントリがある。
- **AC9:** `plugins/just-spec/skills/spec/templates/spec.md`・`templates/overview.md`・`references/ambiguity.md`・`examples/account-deletion.md` が今回の変更で書き換えられていない（`git diff --stat` 等で変更ファイル一覧に含まれないことを示せる）。

## Completion

この節は固定です。無人で実行されても契約が完結しているよう、各 spec に残します。

- 完了とは、全 AC が実行済みの根拠つきで `PASS` であり、AC 別の Evidence 表（AC / 結果 / 根拠）が報告されていることです。部分充足（「主要な AC は満たした」等）は完了ではありません。
- 期待結果は spec から導きます。現在の実装や観測された出力を根拠にしません。根拠には実行した検査の名前・コマンド・観測結果を示し、実行していない検査を `PASS` として報告しません。
- ある AC を満たすと別の AC または Constraint に必ず違反する場合、完了を宣言せず、矛盾の内容とそれまでの試行を報告して停止します。
- 同一 AC への修正が繰り返し失敗する場合、無際限に試行せず、試行の経緯・検出器の出力・原因の仮説を添えて停止します。報告は失敗の宣言ではなく、仕様を変えるか制約を緩めるかという人間が判断すべき点を明示した質問として構成します。
- 完了時に、この spec の `status` を全 AC PASS なら `verified`、そうでなければ `partial` に更新します。

## Decisions

- **D1:** 上限値は 10 ターンとし、SKILL.md に直書きする。
  - 捨てた主要案: 上限の設定可能化、spec 規模に応じた可変化。発動が観測されてから検討する。
- **D2:** 🤖 上限到達時の報告要求は提示行（`/goal` の条件文）にのみ含め、spec テンプレートの Completion 節には追加しない。
  - 🤖 根拠: ハンドオフが spec フォーマットの変更を対象外としている。ターン数は実行セッションの属性であり、`/goal` の評価器が会話から判定する事項なので、条件文が正しい置き場所である。
- **D3:** 🤖 `validate.mjs` に上限節の不変フレーズ検査を追加する。
  - 捨てた主要案: 検査を追加しない案。
  - 🤖 根拠: 提示行は実行時規律の運び手であり、0.7.0 の判断（固定節の存在検査。goal-handoff の D5）と同じ理由で、欠落を CI で検出できないと規律が静かに失われる。
- **D4:** 🤖 SKILL.md の語数予算（1250語）は、上限節の追加に必要な最小限だけ `validate.mjs` 側で引き上げてよい。既存本文の刈り込みで収めることを要求しない。
  - 捨てた主要案: 既存の文を削って 1250 語に収める案。
  - 🤖 根拠: 現在ちょうど 1250/1250 で余裕がなく、既存本文は不変フレーズと契約を運ぶ規律文で構成されている。数十語の削減がそれらを弱めるリスクのほうが、予算の最小限の引き上げより大きい。
  - 不変条件: 引き上げは今回の追加分に見合う幅に留め、予算検査そのものは維持する。
- **D5:** 🤖 バージョンは 0.7.2 とする — 全リリースでバージョンを上げるリポジトリの慣習と、`validate.mjs` の3マニフェスト一致検査に従う。
- **D6:** 🤖 この spec の AC は、文書内容の確認と `node scripts/validate.mjs` の実行で検証する。ハンドオフの検証手順1〜2（実際の `/spec` 実走と提示行の比較）および4（上限到達の挙動確認）は、実装後に人間が別セッションで実施する — goal-handoff spec の D3 と同じ判断。定型性（AC2）はひな形の可変部分がパスのみであることの文書確認で代替する。

## Constraints

- 提示行の可変部分は spec のパスのみ。長さは spec の規模によらず一定で、パスを埋めた実体が 1,000 文字以内を保つ。
- 上限節の文言は、既存の提示行の文体（spec の実装を命じる指示文の連なり）に合わせる。
- `README.md` と `README.ja.md` は同等の内容を保つ。
- スキルの対話フロー・spec テンプレート・質問判定規則（`references/ambiguity.md` を含む）を変更しない。
- 既存の `.just-spec/specs/` 配下の他の spec は書き換えない。
- `plugins/just-spec/skills/spec/SKILL.md` は `validate.mjs` の語数予算検査を通る（D4 の引き上げを含めて整合させる）。

## Out of Scope

- 上限値の設定機能・spec 規模に応じた可変化。
- 時間ベースの上限（stop after N minutes 等）。ターン上限のみとする。
- 対話フロー・spec フォーマット・質問判定規則の変更。
- 上限到達時の自動リトライ・自動エスカレーション機構。報告して止まるのみで、次の行動は人間が決める。
- ハンドオフの検証手順1〜2・4 の実施（実装後に人間が別セッションで行う）。

## Dependencies and Shared Contracts

- Claude Code の `/goal`。条件文の上限は 4,000 文字。公式ドキュメントはターンまたは時間の上限節（例: `or stop after 20 turns`）を条件に含めることを推奨しており、Claude は毎ターンその節への進捗を報告し、評価器は会話に出力された内容のみから判定する。
